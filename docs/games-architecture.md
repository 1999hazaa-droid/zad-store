# البنية التقنية لألعاب زاد المجانية

هذا الملف يشرح كيف ترتبط الأنظمة ببعضها، ليسهل صيانتها دون تكرار البيانات.

## مصدر واحد لكل شيء
| ما هو | أين | ملاحظات |
|---|---|---|
| تعريف اللعبة | `D(id, icon, title, sub, [colors], fn)` في `games/games.js` | يُسجَّل في المصفوفة `K` |
| المراحل (أعمار/صفوف) | `st` ثم `ZCAT[stage].cats` | `zstg(sid)` ألعاب المرحلة، `zstc(sid)` أقسامها |
| **السجلّ الموحّد** | `ZREG.get(id)` / `ZREG.all()` | يجمع: العمر، الصف، القسم، المهارات، المسار، المستويات + حالة الطفل (اكتمال، نجوم، محاولات، آخر لعب) |
| الألعاب الموقوفة | `ZHOLD` في `games.js` | لعبة تُضاف إليه تختفي من كل الواجهات فورًا |
| الحالة والفحص الآلي | `games/registry.json` ← `tools/build_registry.py` | معتمدة / تحتاج مراجعة / فيها أخطاء / تحتاج تحديثًا؛ تُعرض في `games/status.html` |

## مسار بيانات الطفل (يُكتب مرة واحدة ويقرؤه الجميع)
اللعبة تنتهي ← `T()` (شاشة الفوز الموحّدة) ← `zsave()` / `zlog` تكتب في `localStorage` (مفاتيح بصيغة `hg_*:اسم الطفل`):

- `hg_log`: سجلّ كل محاولة منتهية `{i: اللعبة, l: المستوى, s: النجوم, d: التاريخ}`
- `hg_lv`: نجوم كل مستوى لكل لعبة `[تعلّم, تدريب, تحدّي, إتقان]`
- `hg_prog` / `hg_daily`: نجوم الألعاب غير المستوية والتحدّي اليومي والسلسلة
- `hg_gs`: ألعاب بدأها ولم يكملها · `hg_mist`: أخطاء للمراجعة
- `hg_awd`: تاريخ حصوله على كل شارة/كأس (لا تُحتسب مرتين ولا تضيع)
- `hg_chal`: أسابيع أكمل فيها تحدّيات الصفوف

ثم تقرأ هذه البيانات نفسها الأنظمة التالية ولا تخزّن نسخة خاصة بها:

| النظام | الدوال |
|---|---|
| التقدّم والمتابعة | `zpl`, `zget`, `zbest`, `zmast`, `zstr` |
| التقييم والمهارات | `zgsk`, `zarea`, `zskg`, `zpdAreaDone` |
| المكافآت | `_e` (الشارات) + `ZSKB` (شارات المهارات) + `zrw` (كؤوس وأقسام) + `zawnew` |
| التوصيات والمسارات | `zpaths`, `zrecNow`, `zrecCard`, `zchal` |
| لوحة ولي الأمر | `zpd`, `zpdPath`, `zpdAch` |
| المزامنة بين الأجهزة | `zsync`, `zmj` (Supabase `games_saves`) |

## الصوت
مفتاحان فقط في كل شاشة: `#vmute` (صوت زوزو والمؤثرات) و`#mute` (الموسيقى). الموسيقى بمستوى .07 والمؤثرات .5 وسرعة الصوت `ZCFG.voiceRate` (.85). عند كتم الصوت لا يُشغَّل أي ملف.

## الفحص قبل أي نشر
1. `node --check games/games.js`
2. تشغيل سكربتات `tools/audit/` (`audit3.py` لكل لعبة، `e2e.py` لتكامل الأنظمة، `audio.py` للصوت؛ مساراتها مكتوبة على `/tmp/rd` فعدّلها حسب بيئتك): كل لعبة تُلعب حتى الفوز على الهاتف والتابلت والكمبيوتر.
3. `python3 tools/build_registry.py phone=… tablet=… desktop=…`
4. `python3 tools/build_offline.py` ثم رفع رقم النسخة في `games/index.html`.

## دورة حياة اللعبة الموحّدة (zlife)
كل لعبة تمر عبر نقطة دخول واحدة، وتُطلق أحداثًا على `document` باسم `zlife` (`detail.ev`): `open` (فتح) ← `begin` (بدء التشغيل) ← `progress` (تقدّم) ← `end` (نهاية، `recorded` تعني حُفظ التقدم) ← `replay` (إعادة) / `exit` (خروج) / `error` (خطأ).
- حدّ الأخطاء `zfail`: أي استثناء داخل اللعبة يُسجَّل محليًا (`hg_err`) ويُظهر بطاقة «لحظة صغيرة!» بزر رجوع بدل شاشة فارغة.
- التحقق: `tools/audit/audit4.py` (يسجل تسلسل الأحداث لكل لعبة) ← `results_life_phone.json` ← حقل `contract` في `games/registry.json`.
- النتيجة على الهاتف: 383 لعبة فُحصت، كلها `open`+`begin` بلا `error`؛ 22 لعبة لا يُكمِلها الروبوت العام (تُختبر بحلّالات خاصة) فتحقق منها حتى `progress` فقط.
- الألعاب القديمة الـ19 (غير الظاهرة في مرحلة) محفوظة بلا حذف، واختُبرت: تفتح وتُكمل بلا أخطاء؛ حالتها `legacy` في السجل (`tools/audit/legacy.json`).
