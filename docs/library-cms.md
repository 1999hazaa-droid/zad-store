# نظام إدارة محتوى المكتبة (زاد)

**أين:** لوحة `/manage/` ← «المزيد» ← «إدارة المكتبة». الدخول بحساب المدير نفسه (جدول `admin_users`).

## البنية
- المحتوى = صفوف `products` التي لها `lib_section` (لم تتغير الروابط ولا الملفات القديمة).
- حقول جديدة: `lib_status` (draft/review/published/unpublished)، `lib_type`، `lib_unit`، `lib_keywords`، `lib_order`.
- **لا يظهر للزوار إلا المنشور**: الزناد `lib_sync_status` يربط الحالة بـ `is_visible` في الاتجاهين (والقراءة العامة تعتمد `is_visible`).
- `lib_audit`: سجل لا يُعدَّل (إضافة/تعديل/حالة/حذف/استعادة، قبل وبعد). يقرؤه المدير فقط. الحذف يحفظ أيضًا صور المعاينة.
- `lib_restore(id)` استعادة نسخة سابقة (مدير فقط). `lib_set_order(ids)` ترتيب يدوي. `lib_rename_subject` إعادة تسمية مادة مع تحديث ملفاتها.
- `lib_taxonomy`: الأعمار والصفوف (1–6) والمواد والأنواع والأقسام والمهارات والوحدات؛ تعديلها لا يمس الملفات. المكتبة العامة تقرأ الأسماء والإضافات منها.
- النسخ الاحتياطي: `lib_backup_20261118` و`lib_backup_media_20261118` (قبل أي تعديل) + زر «نسخة احتياطية» ينزّل JSON.

## الاختبارات
- `tools/audit/` (واجهة الإدارة بمحاكي قاعدة بيانات): `admin_ui_t1/t2/t3.py` + `admin_mock.py`.
- قاعدة البيانات: اختبارات SQL داخل معاملة تُلغى (زائر/طفل/مدير، نشر/إلغاء/استعادة/حذف).

## حدود معروفة
- رفع الملفات الحقيقي إلى المخزن وتسجيل الدخول الفعلي لم يُجرَّبا من بيئة التطوير (لا حساب ولا وصول للمخزن).
- كشف تكرار الملفات: تحذير عند تطابق العنوان فقط (لا بصمة للملفات).
